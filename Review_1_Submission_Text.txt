1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
In an e-commerce platform running hundreds of recommendation experiments, historical predictions cannot be reconstructed for audit because training data, feature states, source code commits, hyperparameters, and deployments evolve without immutable linkage. 
Traditional ML systems fail due to:
  1. Feature Drift / Lookahead Bias: Feature stores continually overwrite historical tables. Re-evaluating past predictions queries mutated current profiles.
  2. Decoupled Model Lineage: Model artifacts are overwritten without cryptographic hashes or Git commit SHAs.
  3. Stream Chaos: Distributed pipelines experience delayed, duplicate, and out-of-order events.
This project implements an end-to-end Model-Reproducibility Registry coupled with a Point-in-Time Feature Store and Cyber Forensic HUD, guaranteeing 100% bit-exact prediction reconstruction (0.0000 score delta) and complete stream fault-tolerance.

2. STAKEHOLDER ASSUMPTIONS & REQUIREMENTS
* Data Engineering: Distributed streams are lossy, delayed, and replayed. Requirement: Idempotent deduplication (SHA-256 keys) and zero lookahead bias.
* ML Engineers: Retraining must never break past explainability. Requirement: Binding dataset snapshots (SHA-256), Git SHAs, hyperparameters, and artifact hashes.
* Compliance / Audit Officers: Predictions must be verifiable on-demand. Requirement: 1-Click audit endpoint proving 0.0 delta and exporting official plain text/CSV certificates.
* MLOps / Deployment Ops: Only validated models may serve traffic. Requirement: Formal approval records gating production deployment records.

3. SYSTEM ARCHITECTURE & 4-LAYER DESIGN
* Layer 1: Cyber Forensic HUD: Live recommendation store, 1-click audit inspector, tamper lab, chaos stream simulator, and model evolution matrix.
* Layer 2: FastAPI Backend: /api/recommend (immutable audit log), /api/audit/{id} (time-travel reconstruction), /api/security/tamper & restore, /api/models/train-v2, /api/export/csv.
* Layer 3: Relational Registry: Tracks dataset versions, model records, approval records, deployment states, and immutable inference audit logs.
* Layer 4: Point-in-Time Feature Store: As-of time-travel query engine (WHERE event_timestamp <= inference_timestamp) with idempotent deduplication.

4. RELATIONAL DATA SCHEMA
Database: SQLite (data/registry.db) with 7 relational entities:
  1. dataset_versions: id, dataset_name, version_tag, sha256_hash, storage_path, schema_json, record_count, created_at.
  2. feature_definitions: id, feature_name, entity_type, data_type, transformation_logic, version, created_at.
  3. model_records: id, model_name, version_tag, git_commit_sha, git_branch, hyperparameters_json, metrics_json, artifact_path, artifact_sha256, training_dataset_id, created_at.
  4. approval_records: id, model_id, approver, status (APPROVED/REJECTED), comments, decided_at.
  5. deployment_records: id, model_id, environment (production/staging), is_active, deployed_by, deployed_at.
  6. inference_audit_logs: id, inference_id (UUID), timestamp, user_id, candidate_items_json, features_snapshot_json, model_id, deployment_id, raw_scores_json, recommendations_json.
  7. feature_store_events: id, event_key (SHA-256 unique), entity_id, entity_type, event_type, item_category, value, event_timestamp, ingested_at.

6. ADVERSARIAL STRESS TESTING & FOUR EDGE CASES
  1. Replayed Duplicate Events (Idempotency): Ingestion engine computes deterministic SHA-256 fingerprint: (entity_id, type, value, timestamp). Duplicate packets safely intercepted; 0 duplicate rows created.
  2. Delayed / Late-Arriving Events (Zero Lookahead Bias): Late events arriving 5 days after inference are isolated by timestamp watermarks; past point-in-time snapshots remain unaffected.
  3. Out-of-Order Streams: Scrambled event streams are aggregated deterministically over ordered chronological windows with zero state corruption.
  4. Malicious Physical Model Tampering: Modifying 1 byte on disk triggers cryptographic SHA-256 mismatch: [SECURITY_BREACH] Physical Checksum Compromised, locking inference execution.
